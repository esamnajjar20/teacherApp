# تطبيق المعلمين (Teacher App)

تطبيق Flutter كامل لإدارة الحضور والدرجات والتقارير للمعلمين.

## التقنيات
- Flutter (`setState` + طبقة بيانات `DatabaseService` فوق SQLite محلية)
- Supabase (Auth + PostgreSQL + RLS)
- Excel export
- دعم عربي كامل (RTL)

## الميزات المكتملة
- تسجيل دخول / إنشاء حساب
- إدارة الفصول (إضافة / تعديل / حذف مع تحذير بما سيختفي)
- سلة المحذوفات: استعادة الفصول والطلاب والتقييمات
- سجل الحضور السابق لكل فصل مع تعديل الجلسة وحذفها
- تعديل التقييم (الاسم والوزن والدرجة العظمى والنوع والتاريخ وإيقاف احتسابه)
- إضافة عدة طلاب دفعة واحدة: لصق قائمة أو استيراد ملف Excel (.xlsx) / CSV
- إدخال أسرع: زر «التالي» في الدرجات، «الكل حاضر/غائب»، والضغط المطوّل لاختيار الحالة، وتنبيه عند الخروج دون حفظ
- تعديل اسم المعلم من «حسابي»، وإعادة إرسال رمز تأكيد البريد
- تسجيل الخروج يحذّر من التعديلات التي لم تُرفع
- إدارة الطلاب
- ربط الطلاب بالفصول (Enrollment)
- تسجيل الحضور (حاضر / غائب / متأخر / بعذر) مع الافتراضي = حاضر
- إدارة التقييمات والأوزان
- إدخال الدرجات
- تصدير كشف الدرجات إلى Excel (مع المعدل والتقدير)
- إعدادات الدرجات لكل فصل: سياسة الدرجة الناقصة وسلم التقديرات (زر الإعدادات في شاشة التقييمات)
- تقرير الحضور لفترة محددة مع نسبة الحضور لكل طالب وتصدير Excel (ورقتان: ملخص وتفصيل يومي)
- استعادة كلمة المرور برمز البريد (قالب Reset Password في Supabase يجب أن يحتوي `{{ .Token }}`)
- شاشة "حسابي": حالة المزامنة، تغيير كلمة المرور، حذف الحساب (تتضمنه migrations: `delete_my_account`)
- ملف الطالب (حضوره ومعدله وترتيبه في كل فصل) ونتائج الفصل مع الترتيب والتقدير
- تعديل بيانات الفصل
- البحث في الطلاب وتعديل بياناتهم، ومنع تكرار رقم الطالب، وإضافة عدة طلاب للفصل دفعة واحدة
- Soft Delete على كل الكيانات
- RLS جاهز

## خطوات التشغيل

1. أنشئ مشروع Supabase
2. أنشئ قاعدة البيانات من مجلد `supabase/migrations/` (هو المصدر الوحيد لبنية القاعدة،
   وكل ملف فيه آمن لإعادة التشغيل). إما:
   - `supabase db push` (Supabase CLI)، أو
   - تنفيذ الملفات بالترتيب الزمني لأسمائها في SQL Editor أو عبر `./run_sql.sh`.
   - الملف `20261020000001_student_code_unique.sql` يفشل عمداً إن كان عندك طلاب بأرقام مكررة
     لنفس المعلم؛ عدّل المكرر (الاستعلام الكاشف داخل رسالة الخطأ) ثم أعد التشغيل.
   - إن أبقيت «Confirm email» مفعّلاً في Supabase فقالب **Confirm signup** يجب أن يحتوي
     `{{ .Token }}` ليصل رمز من 6 أرقام (Authentication → Email Templates)؛ التطبيق يطلب الرمز
     ولا يعتمد على الرابط. شاشة الرمز فيها «إعادة إرسال»، والدخول بحساب غير مؤكَّد يفتحها تلقائياً.
3. شغّل التطبيق مع تمرير المفاتيح (لا تضعها داخل الكود):
```bash
flutter pub get
flutter run \
  --dart-define=SUPABASE_URL=https://xxxx.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=eyJ...
```
4. للبناء عبر GitHub Actions أضف السرّين `SUPABASE_URL` و `SUPABASE_ANON_KEY`
   في Settings → Secrets and variables → Actions. يشغّل الـ CI عند كل push: `flutter analyze` ثم
   `flutter test` (يفشل إن فشل أحدهما)، ثم يبني الـ APK على فرع main.

### Android
- مجلد `android/` يُولَّد في الـ CI إن لم يكن في المستودع، ثم يُشغَّل `tools/customize_android.sh`
  (اسم التطبيق، صلاحية الإنترنت، compileSdk، الأيقونة من `assets/icon/`).
- لتثبيته في المستودع بدل توليده كل مرة:
  ```bash
  flutter create --platforms=android --project-name=teacher_app --org=com.esamnajjar20 .
  bash tools/customize_android.sh
  git add android && git commit -m "Add android platform"
  ```
- خط Cairo: ضع ملفاته في `assets/google_fonts/` (انظر README هناك) ليعمل بلا إنترنت.

## العمل بدون إنترنت والمزامنة
- كل القراءة والكتابة تتم على قاعدة SQLite محلية (`sqflite`) لكل مستخدم، فيعمل التطبيق كاملاً بدون اتصال.
- كل تعديل يُعلَّم للرفع ثم يُرفع تلقائياً عند توفر الإنترنت، ويُسحب ما تغيّر على السيرفر (كل 45 ثانية، وعند عودة الاتصال، وبعد كل حفظ، وبزر المزامنة في الشريط العلوي).
- التعارض: **آخر رفع يفوز**. التعديل المحلي الذي لم يُرفع لا يُكتب فوقه عند السحب.
- السحب يستمر حتى صفحة فارغة، فلا يتأثر بإعداد Max Rows في Supabase.
- السجل الذي يفشل رفعه (مثل رقم طالب مكرر على الخادم) يُعزل ويُعاد بتأخير تصاعدي (دقيقة حتى 30 دقيقة)،
  ويظهر باسمه وسبب الفشل في «حسابي». زر «مزامنة الآن» يتجاوز التأخير، وتعديل السجل يعيد المحاولة فوراً.
- أول تسجيل دخول يحتاج إنترنت. بعده تبقى الجلسة محفوظة.
- فهارس المزامنة ضمن `supabase/migrations/20261018000002_create_indexes.sql`.
- بيانات الجهاز غير مشفّرة (ملف SQLite عادي).

## منطق التقارير
- **نسبة الحضور** = (حاضر + متأخر) ÷ (كل الجلسات − بعذر) × 100. المتأخر يُعدّ حاضراً، والغياب بعذر لا يُحتسب لا للطالب ولا عليه.
- يُنبَّه إلى الطالب إذا نزلت نسبته عن 75% (`AttendanceCalculator.warningThreshold`).
- التقرير يشمل طلاب الفصل الحاليين فقط، وجلسات الفترة المختارة غير المحذوفة.
- **التقدير** يؤخذ من سلم الفصل (أعلى حدّ أدنى تبلغه النسبة). السلم الافتراضي: ممتاز 90، جيد جداً 80، جيد 70، مقبول 60، ضعيف 0.
